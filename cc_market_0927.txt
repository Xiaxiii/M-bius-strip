一、写进 CLAUDE.md 的决定（第1段开头就写，接在最后一节之后，编号顺延）
########################################
黑市：面板页签「黑市」，位于「账本」与「设置」之间，分「盘口」「票夹」「赌坊」三个小页签。
盘口：押的是{{user}}自己这一局的故事。入场确认后开盘，入场后第2条AI回复到来时封盘，封盘后不再重开。休整副本（rest: true）不开盘。
盘口分三种：结局盘与评价盘（所有副本都有）；事件盘（写在副本包 markets 字段里）；庄家怪盘（开盘时由副API按公开信息现场出2–3题）。事件盘和庄家怪盘靠副本事件检测判定，事件检测来源为「关闭」时这两种不开。
赔率：赔率 = 1 ÷ 概率 × 0.8（庄家抽水20%）× 0.93–1.07 的随机浮动，保留两位小数，最低1.01，开盘时定下不再变。绝不按剧情真相定赔率。
押注：单个盘口累计押注上限按玩家等级 D 1,000、C 5,000、B 20,000、A 80,000、S 300,000，最低10；不能超过当前可用余额（副本内要扣掉本局直播打赏）。押完余额低于斩杀线时红字提示，不拦截。押自己失败也可以，交给剧情。
赌坊：即开即结的小游戏，共「听钟」「门牌」「抽签」「翻牌」四张桌，每次回到回廊随机摆出两张；默认只在回廊营业，副本包 casino: true 的副本内也营业。所有玩法长期期望都是押注的80%。
流水：下注、兑付、退还、赌坊每局各记一行，账本类型 bet。

【第1段】数据与计算（纯函数，不接界面）
########################################
1. 事件盘数据：仓库最外层的 markets.json 按副本 id 迁进对应副本包（zhonglou、dusongshu、jingjie、xiyan、youxi）的新可选字段 markets，每条格式不变；packs/ 下的同名文件同步。loader 校验：markets 为数组；每条要有 id、q、yes、no、judge 文本，p 为 0.01–0.99 的数；judgeNo 可选文本；by 可选，必须是本包阶段 id，否则该条跳过并在控制台警告。五个包各升一个小版本号。说明数组不用迁。

2. 新建黑市计算模块（纯函数，随机数通过参数传入）：
2.1 等级序：D=0、C=1、B=2、A=3、S=4。差 = 副本等级序 − 玩家等级序。玩家等级取法与账本相同。通用副本的副本等级取简报的「等级」。
2.2 结局盘「本局结果」：选项「通关」「失败」。通关概率按差：≤−2 为 0.85；−1 为 0.75；0 为 0.6；+1 为 0.4；+2 为 0.25；≥+3 为 0.15。失败 = 1 − 通关。
2.3 评价盘「本局评价」：选项 S、A、B、C、D，概率按差：
    ≤−1：S 0.15　A 0.30　B 0.30　C 0.17　D 0.08
    0：  S 0.08　A 0.20　B 0.35　C 0.25　D 0.12
    +1： S 0.04　A 0.12　B 0.30　C 0.32　D 0.22
    ≥+2：S 0.02　A 0.08　B 0.25　C 0.35　D 0.30
2.4 事件盘、庄家怪盘：是 = p，否 = 1 − p。
2.5 赔率：每个选项 odds = max(1.01, 保留两位小数((1 ÷ 概率) × 0.8 × 浮动))，浮动 = 0.93 + 随机数 × 0.14，每个选项各抽一次。
2.6 上限：单盘累计上限见上面的决定；最低10；可用余额 = 当前余额 − 本局已到账直播打赏（回廊中不扣）。返回是否可押、以及押完是否低于斩杀线。
2.7 兑付金额 = 向下取整(押注 × 赔率)。

3. 开奖规则（纯函数，输入：本局的盘口、赌票、重放得到的结算结果和每轮事件检测结果）：
- 结局盘：<副本结算> 结果=通关 → 押「通关」兑；结果=失败 → 押「失败」兑；另一边废。
- 评价盘：通关且评价为 S–D → 押中的兑，其余废；失败、或评价为「无」或读不出 → 全部退。
- 事件盘、庄家怪盘：某一轮检测判定 judge 为真 → 押「是」兑、押「否」废，立即开奖；判定 judgeNo 为真 → 反过来。带 by 的：该阶段结束时仍未判出，按「未判出」处理；不带 by 的：副本结算时处理。「未判出」时：盘口开着的这段时间里每一轮都成功做过事件检测（没有跳过、失败或关闭）→ 押「否」兑、押「是」废；否则全部退。
- 结果=死亡（含「阵亡」）：本局所有还没开奖的赌票全部废。
- 手动结束副本（没有 <副本结算>）、或会话作废：还没开奖的全部退。
- 开奖结果由重放得出：删楼、重新生成、滑动后自动重算，已兑付的会撤回。

4. 赌坊（纯函数）：
- 听钟：钟响 1–12 下，均匀。押「单」「双」各赔 ×1.6；押「小」（1–6）「大」（7–12）各赔 ×1.6；猜具体下数赔 ×9.6。
- 门牌：1–20 号门，均匀。押单个号码赔 ×16；押一段「1–5」「6–10」「11–15」「16–20」赔 ×3.2。
- 抽签：三支签一支大吉，押中赔 ×2.4。
- 翻牌：{{user}}和庄家各从 1–13 独立均匀翻一张，{{user}}大才赢，平局庄家赢，赢赔 ×1.73。
- 赔付 = 向下取整(押注 × 倍数)；输了拿不回押注。
- 摆桌：四张里随机选两张。每次副本结束（结算或手动结束）回到回廊、或聊天里没有摆桌记录时重新抽；存在 chatMetadata，面板反复打开不变。
单元测试：以上每条，包括赔率公式与最低1.01、各差值的概率表、上限与可用余额（副本内扣打赏）、各种开奖情况（含 by、judgeNo、检测有跳过时退、死亡全废、手动结束全退）、四个游戏的期望值在 0.8 附近（大量模拟）、摆桌只在回到回廊时重抽。

########################################
【第2段】接入流程
########################################
1. 开盘：入场确认后（休整副本除外）立即开结局盘、评价盘，以及本包 markets 里的事件盘（事件检测来源为「关闭」时不开事件盘）。盘口、赔率、赌票存 chatMetadata.rlzc_market（按会话 id 分开），不随删楼回滚；开奖结果按上面的规则由重放得出。
2. 庄家怪盘：事件检测来源不是「关闭」时，入场确认后另发一次独立调用出题（接口跟随事件检测卡的来源与预设），不和事件检测合并，不等待、不阻塞。输入只有：副本名、等级、简报原文、副本包 docs 的公开资料（合并后截到4000字）。不得带入事件表、隐藏状态、事件检测结果、事件盘数据。提示词照用：
「你是回廊黑市的庄家，要为主播即将进入的副本开几个离谱但有趣的盘口。你只知道下面这些公开信息，不知道剧情会怎么走。出2到3道是非题：题目20字以内，称{{user}}为主播，不用性别代词；必须能从之后的正文里直接看出是或否；不要问结局、评价和生死，那些已经有盘了；不要涉及公开信息以外的设定。每题给一个你估计「是」的概率p（0.05到0.95）。只输出JSON：[{"q":"题目","judge":"用来判断是否发生的一句陈述","p":0.3}]」
解析方式同事件检测；不合格的题丢掉；失败重试1次，仍失败这局不开怪盘，不弹窗，调试页记原因。选项文字固定「会」「不会」。出题结果晚于封盘到达时丢弃。
3. 封盘：会话重放出入场后第2条AI回复时封盘，记下封盘时间，之后删楼也不重开。
4. 下注：记一笔 −押注（类型 bet，挂在 chatMetadata 的记录里，不随删楼撤销），流水写「下注·钟楼·本局结果·通关」（副本名、盘口题目、选项换成实际的）。兑付记 +兑付金额，流水「赌票兑付·钟楼·本局结果」；退还记 +押注，流水「赌票退还·钟楼·本局结果」；这两种由重放得出，随删楼撤销。
5. 事件检测：盘口开着且有未开奖的事件盘、怪盘时，在事件检测的输出 JSON 里加字段 "markets": {"盘口id": true/false}，提示词里列出每个盘口的 judge（有 judgeNo 的另列一条，id 后加 :no），要求「只有本轮正文明确写到才填 true」，不要理由。缺少这个字段不算检测失败，但这一轮对盘口算「没检测」。这些内容不注入主AI。
6. 给主AI的一次性提示（加在下一次正常生成的［账户·仅供AI］末尾，只加一次）：
- {{user}}押了自己本局「失败」时：「{{user}}在黑市押了自己本局失败，押注X分。」
- 赌坊一局输完余额低于斩杀线时：「{{user}}刚在赌坊输掉X分，余额已低于斩杀线。」
- 赌坊一局赢的钱超过单注上限的5倍时：「{{user}}刚在赌坊一局赢了X分。」
7. 开奖提示：有赌票开奖时弹一次提示「赌票开奖：兑 N 张，废 N 张，退 N 张。」（为0的项不写）。悬浮球右上角显示待开奖赌票张数，没有时不显示。
8. 赌坊：每局记一行，金额为净得失（赢为 +(赔付−押注)，输为 −押注），类型 bet，存 chatMetadata，不随删楼撤销，流水写「赌坊·听钟·押单」（桌名和押法换成实际的）。
单元测试：开盘时机与休整副本不开；检测关闭时只开结局盘和评价盘；封盘后不重开；下注扣款与可用余额；怪盘请求内容里没有事件表、隐藏状态、事件盘数据；怪盘失败不开且不弹窗；事件检测 JSON 缺 markets 不算失败；一次性提示只出现一次；删楼后兑付撤回、下注不撤回；赌坊记账。

按 CLAUDE.md 的界面规则，跟随酒馆深浅色主题，可点区域不小于44px，390px 宽不出现横向滚动。文字照写。

2. 盘口：
- 顶部状态卡一行：开盘中「《钟楼》开盘中 · 第1轮结束封盘」；已封盘「《钟楼》已封盘」；没有副本「进副本后开盘。」；休整副本「休整副本不开盘。」
- 每个盘口一张卡：左上角小标签「结局」「评价」「事件」「庄家」之一，后面是题目；结局盘题目「本局结果」，评价盘题目「本局评价」。下面是选项按钮网格（两项两列，五项自动换行），每个按钮左边选项文字、右边赔率「×1.45」。
- 选中一个选项后，这张卡下方出现一行：押注输入框（占位「押多少」）+ 按钮「下注」；再下一行小字「单注上限 1,000（D级）」；押完低于斩杀线时再加一行红字「押完余额低于斩杀线」。已封盘时按钮不可点，赌票照常显示。
3. 票夹：新的在上，一行一张。左边上行「钟楼 · 本局结果 · 通关」，下行小字：待开奖「押 500 · ×1.45 · 待开奖」、兑「押 200 · ×3.10 · 兑 620」、废「押 100 · ×2.40」、退「押 50 · 原数退还」。右边一个圆形章，略微倾斜：「兑」用成功色、「废」用危险色、「退」用次要文字色、「待」用虚线圈且不倾斜。没有赌票时一行「还没有赌票。」
4. 赌坊：
- 顶部一行「今晚开两张桌，回到回廊换一批。」；不营业时只显示「赌坊只在回廊营业。」
- 两张桌并排两列，每张写桌名和一句话：听钟「押钟声单双、大小，或猜几下。」门牌「押指针停在哪扇门。」抽签「三支签，一支大吉。」翻牌「和庄家各翻一张，大的赢，平局庄家赢。」
- 点开一张桌：选押法（分段按钮或网格）→ 押注输入框（占位「押多少」）→ 按钮「开」。上限、低于斩杀线红字同盘口。开奖有不超过1.5秒的简单动画（系统设置减少动态效果时不播），然后一行结果：「结果：7下，单。赢 160」或「结果：12号门。输 100」。
5. 设置、系统、账本页不加黑市内容。调试页加一栏：本局各盘口的赔率、每轮检测对盘口的判定、怪盘出题结果或失败原因。
