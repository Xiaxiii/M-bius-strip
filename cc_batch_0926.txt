【第2段】直播计算（纯函数，不接界面）
########################################
新建一个直播模块，只写纯函数和单元测试，暂时不接入消息流程。随机数通过参数传入，方便测试。

1. 精彩度 hype（0–100）
- 有事件检测结果且带 hype 字段：直接用。
- 否则按规则：基础20；本轮有注入事件 +20；本轮阶段切换 +20；本轮有人受伤或死亡 +30；上限100。
- 受伤、死亡判断：有事件检测结果且带 hurt 字段就用它；否则用关键词判断正文，词表自定，写进测试。

2. 热度 heat（0–100）= 上一轮热度×0.6 + 本轮精彩度×0.4，取整。开播第一轮的上一轮热度为20。

3. 观看人数
- 基数：D 2000、C 8000、B 30000、A 100000、S 300000。
- 副本内用副本等级；回廊中用玩家等级（最近一条 <状态栏> 里{{user}}的「等级」，读不到按D），再乘0.3。
- 休整副本（副本包 rest: true）的人数、打赏金额和本地弹幕范围都按回廊算。
- 人数 = 基数 ×（0.5 + 热度/100）× 0.9到1.1之间的随机数，取整。

4. 打赏
- 笔数：期望笔数 = 精彩度 ÷ 40，最多3笔。
- 金额：10、20、50 合计约60%；100、200 约30%；500 约8%；1000 约2%。精彩度≥70 时，500 和 1000 的概率翻倍，多出来的从 10、20 里扣。
- 回廊中金额 ×0.3，取整到10，最少10。
- 打赏人名字从弹幕池 names 随机。
- 每笔实到 = 金额×60%，向下取整。
- 本轮合并成一条账本记录（类型 tip）：一笔写「直播打赏500×60%」；多笔写「直播打赏3笔·共650×60%」，金额为实到合计。

5. 本地弹幕抽取
- 每轮5–8条。
- scope：inst 只在副本，corr 只在回廊，没写=都可以。
- when：hurt 只在本轮有人受伤或死亡时可抽；calm 只在本轮精彩度低于30时可抽；open 在开播后前两轮提高概率；end 在剩余轮次不足上限一成时提高概率；没写=任何时候。
- 副本包有 danmaku 时，每条约三成概率从专属里抽；带 phase 的只在这些阶段可抽。
- templates 的 {who}：用最近一条 <状态栏> 里角色详情块的「角色名」，不含{{user}}；没有可用名字就不抽 templates。
- 同一条文字在最近30条里不重复。发言人名字从 names 随机。

单元测试：以上每一条都要有，包括边界（精彩度0和100、回廊最少10、hurt 条目只在受伤轮出现、没有角色名不出 templates）。
完成后提交并推送到 GitHub。

【第3段】接入流程：开播、记账、回滚、接口
########################################
1. 入场弹窗：加勾选框「开启直播」，默认不勾；上次选择存在 extensionSettings.rlzc，下次沿用。点「是」后本局直播状态锁定，副本结算或手动结束副本时自动下播。disableLive 副本不显示勾选框、不开直播。通用副本也可以直播，只是没有专属弹幕。
2. 回廊直播：没有进行中副本时可开播、下播，状态存 chatMetadata，不随删楼回滚。从开播到下播为「一场」。进入副本时若正在回廊直播，自动下播。
3. 每条新AI回复（直播中）：调用第2段的函数，算出精彩度、热度、人数、本轮弹幕、本轮打赏，存进 chat[i].extra.rlzc.live；打赏合并记账到这条消息的账本记录里，之后照常判断待清算。continue 不算新一轮。
4. 回滚：删楼、重新生成、滑动后，按当前显示的回复重放，做法与账本相同。重放后弹幕的 id 从当前最大值继续递增，不复用旧 id。
5. 事件检测：在事件检测的输出 JSON 格式里加两个字段：
   "hype": 0–100 整数，按本轮正文的紧张、冲突、转折打分；
   "hurt": true/false，本轮正文是否有人受伤或死亡。
   提示词只要求数字和真假，不要理由。这两个字段不注入主AI。解析时缺少这两个字段不算失败。
6. 副本内不可花：副本内直播时，［账户·仅供AI］那段末尾加一句「其中本局直播打赏X分，副本内不可使用，离开副本后可用。」X 为本局已到账合计。回廊中不加。
7. 死亡撤回：<副本结算> 结果=死亡，且本局开了直播：记一笔 −本局打赏合计，类型 tip，流水写「本局直播打赏撤回」。失败不撤回。
8. 接口：扩展启用时在酒馆主页面挂 window.RLZC_LIVE，格式如下（行为参考 tests/e2e 素材里的 RLZC_LIVE_mock.js）：

RLZC_LIVE.get() → {
  on: boolean,          // 是否在播
  canToggle: boolean,   // 回廊 true，副本内 false
  scope: 'instance' | 'corridor',
  viewers: number, heat: number(0-100),
  tipTotal: number,     // 本局/本场到账合计（已扣抽成）
  injectToAI: boolean,
  feed: [{ id, t:'msg'|'tip'|'sys', name, text, amount, net }],  // id 唯一递增，最多保留约60条
  lastTip: { id, net } | null
}
RLZC_LIVE.subscribe(fn) → 取消订阅函数   // 数据变化时调用 fn
RLZC_LIVE.toggle()                        // 回廊中开播/下播；副本内返回 false

9. 播放节奏：本轮的弹幕和打赏按每1.5–3秒一条陆续放进 feed，打赏夹在弹幕中间；页面刷新或切换聊天时，未放出的直接补齐。
10. 系统消息（t:'sys'）：开播、下播、进入副本自动下播、打赏撤回时各一条，一句话。

单元测试：勾选框默认与记忆；disableLive；回廊直播进副本自动下播；多笔合并记账；死亡撤回、失败不撤回；账户注入的附加句；删楼、滑动后直播数据与账本一起回滚；重放后 id 递增；事件检测缺 hype/hurt 不算失败。
完成后提交并推送到 GitHub。

1. AI 生成弹幕
- 每3轮一次（频率可设1–10），另外在关键事件那轮加一次：阶段切换、有人受伤或死亡、本轮注入事件被判定为已发生。同一轮最多一次。回廊直播同样规则。
- 接口跟随「副本事件检测」卡选的来源和预设；那张卡来源是「关闭」时只用本地池。
- 这是一次独立调用，不要和事件检测合并。输入只有：最近两轮AI正文（去掉 <副本>、<状态栏> 和所有机器标签）、副本名（回廊中写「回廊」）、在场知道名字的角色名、下面的风格说明、从弹幕池随机抽10条作语气示例。不得带入事件表、隐藏状态、副本包资料、事件检测结果。
- 风格说明（照用）：「你在写回廊直播间的观众弹幕。观众是回廊里的其他玩家，只看得到直播画面。什么人都有：夸赞、祝福、讨论、泼冷水、嫉妒、抹黑、造谣，正面的稍多。每条30字以内，口语，称{{user}}为主播，不用性别代词。只能根据画面里已经发生的事说话，不猜测、不透露画面外的信息。」
- 输出只要 JSON：[{"type":"praise|bless|discuss|cold|envy|smear|rumor","name":"观众昵称","text":"…"}]，8–12条，解析方式同事件检测。
- 失败重试1次；仍失败不弹窗、不阻塞，这一轮用本地池补足，调试页记原因。不等待，不受「等检测完再写下一轮」影响。
- 生成的弹幕并入这一轮的弹幕，一起按节奏放出，也存进 extra.rlzc.live。

2. 弹幕传给主AI（默认关）
- 开启时新增注入 key rlzc_live，scan=false，深度默认4；「注入深度」卡加一行：直播 — 在看人数与最近弹幕
- 内容：［直播·仅供AI］{{user}}正在直播，约12840人在看。最近弹幕：小满：祝平安出来！！／匿名：演的吧……／好运来 打赏500
- 取最近5条（含打赏行）。关闭或没在直播时不注入。

3. 设置页「直播」卡：放在「副本事件检测」卡之后，按 CLAUDE.md 的界面规则做成可折叠卡片（默认收起，标题行右侧显示「直播中」或不显示），展开后样式和「副本事件检测」卡一致（拨动开关、分段按钮、可点区域不小于44px、跟随酒馆深浅色主题）。文字照写，不加别的：
- 标题：直播
- 说明：开播后有观众弹幕和打赏，打赏计入积分。画面在状态栏的直播页。
- 弹幕来源：分段按钮「本地」|「本地+AI」。事件检测来源为「关闭」时「本地+AI」不可选，下面小字：需先在副本事件检测里选接口。
- 生成频率（选「本地+AI」时出现）：左「生成频率」，右「每 [3] 轮」。小字：关键事件时另加一次
- 弹幕传给AI：拨动开关，默认关。小字：主AI能看到最近弹幕

4. 调试页加一栏：每楼的精彩度、热度、人数、打赏明细、AI 生成弹幕的结果或失败原因。面板其他页不加直播画面。

单元测试：生成时机（每N轮、关键事件、同轮最多一次）；请求内容里没有事件表、隐藏状态、副本资料；失败补足且不弹窗；rlzc_live 默认不注入、开启后内容和条数正确。

沿用 tests/e2e 的模拟环境（SillyTavern + 模拟接口 + Playwright）。模拟服务增加弹幕生成的返回，并能模拟失败。

1. 先验证：导入测试素材里的 regex-huilang-statusbar.json 后，状态栏所在的渲染框能读到主页面的 window.RLZC_LIVE：直播页签出现、弹幕实时更新、回廊中按钮能开播下播。读不到时不要改这个正则文件，停下来告诉我原因和你建议的传数据办法。
2. 流程：回廊开播 → 聊几轮 → 进钟楼（勾选直播）→ 跑几轮，含一次有人受伤 → 结算 → 回廊。检查账本流水、注入内容、状态栏直播页。
3. 喜宴不勾直播：没有直播画面、没有 tip 记账。
4. 污名入场不出现勾选框。
5. 钟楼跑到死亡结算：打赏被撤回。
6. 截图：状态栏直播页桌面和390px宽各一张（回廊、副本各一套）；设置页「直播」卡一张。
7. 统计：开「本地+AI」时，弹幕生成调用每次的平均输入、输出 token 数。
8. 账本：回廊→钟楼→结算→回廊一整圈，账本页流水、rlzc_ledger 注入内容、系统页积分全部正确；另测一次已标记待清算时的注入全文。
9. 入场弹窗：新建聊天用喜宴、游戏开场白会弹；已有聊天里AI回复带简报会弹；切换到别的聊天再切回来仍会弹。
10. 设置页「账户校正」：改初始积分、追加一笔、校正等级和位格后，下一轮注入里有校正句，AI回复后校正句消失。
